# Си для ATmega16 на стендах Учтех-Профи

Практический курс программирования микроконтроллера ATmega16 на Си на учебных стендах НПП «Учтех-Профи»: порты и светодиоды, семисегментный индикатор, прерывания и таймеры, часы, счётчик нажатий и дребезг, матричная клавиатура, частотомер и ШИМ. Каждая программа курса собирается avr-gcc без единого предупреждения, её логика проверена тестами на ПК, а подключение каждого задания укладывается в 16 гнёзд панели.

## Для кого

Для взрослых слушателей с производства, которые хотят попробовать инструменты руками: собрать подключение проводами, прошить контроллер, найти ошибку и дописать свою программу. Нужный минимум Си собран в [главе 3](docs/03-si.md).

Практические главы устроены одинаково: задача; таблица подключения со счётом гнёзд; «Пишем вместе» по шагам (фрагмент кода, что должно получиться на стенде, ссылка на полный файл); самостоятельные задания; вопросы для самопроверки. Ответы и полный код решений спрятаны под спойлер «Ответ»: сначала попробуйте сами, потом откройте.

## Стенд в двух словах

На панель «Контроллера ПУ» выведено ровно **16 гнёзд**: PC0, PC1, PB2–PB7, PD0–PD7, все через резисторы 470 Ом. Справа от них четыре гнезда общего провода. Расположение по рисунку в описании стенда:

| Столбец 1 | Столбец 2 | Столбец 3 | Столбец 4 | Справа |
|---|---|---|---|---|
| PC0 | PB4 | PD0 | PD4 | GND |
| PC1 | PB5 | PD1 | PD5 | GND |
| PB2 | PB6 | PD2 | PD6 | GND |
| PB3 | PB7 | PD3 | PD7 | GND |

- Любое задание обязано влезть в эти 16 гнёзд. Поэтому перед каждым заданием стоит таблица подключения и строка «Гнёзд занято: N из 16», а в шапке каждой программы блок ПОДКЛЮЧЕНИЕ. Четыре разряда индикатора (12 линий) и клавиатура 4×4 (8 линий) вместе не помещаются, решения в [главе 10](docs/10-klaviatura.md).
- На панель не выведены: порт A (внутри модуля к нему подключён ЖКИ), PB0 и PB1 (внешние входы таймеров), PC2–PC5 (заняты JTAG), PC6 и PC7 (выводы для часового кварца Timer2).
- Светодиоды «Контроллера ПУ» горят от 0. Кнопки при нажатии дают 0, им нужна подтяжка, защиты от дребезга у них нет.
- Индикатор на занятиях подключали так: сегменты a–g и точка на PD0–PD7 (1 = горит), разряды на PB4–PB7 (0 = разряд включён).
- Если модулей несколько, их общие провода (GND) соединяются. Фьюзы не трогать.
- Чего нет в документации стендов (какой разряд у PB4, маркировка гнёзд модуля периферии, уровни его кнопок и светодиодов, раскладка клавиатуры, тип пищалки, есть ли модуль анализатора), курс не выдумывает: в главах сказано, как проверить это на своём стенде.

Подробно: [глава 1](docs/01-oborudovanie.md).

## Как пользоваться

**Читать** прямо на GitHub: главы по порядку, ссылки между главами и на файлы программ работают в веб-интерфейсе.

**Программы в AVR Studio 4.** В репозитории файлы в UTF-8, а Studio 4 читает Windows-1251. Два способа получить код:

1. Скачать zip из раздела Releases этого репозитория: все программы уже перекодированы в Windows-1251 с переводами строк CRLF, папки те же, что в code/, внутри README.txt с порядком действий в Studio 4.
2. Открыть программу на GitHub, скопировать текст и вставить в .c-файл проекта Studio 4. Русские комментарии сохранятся, если в Windows для программ без поддержки Юникода выбран русский язык, иначе станут знаками «?». Подробности: [глава 2](docs/02-avr-studio.md#кодировка-windows-1251).

Кнопки Raw и «Download raw file» на GitHub дают файл в UTF-8: Studio 4 покажет его комментарии «кракозябрами». Как создать проект, собрать и прошить: [глава 2](docs/02-avr-studio.md#новый-проект).

**Свой стенд.** До первого занятия выясните то, чего нет в документации: что именно и как проверить, сказано в [главе 1](docs/01-oborudovanie.md).

## Проверки

Одна команда из корня репозитория (или из любой папки) проверяет всё:

```
sh tests/run.sh
```

1. **Сборка** ([tests/build.sh](tests/build.sh)). Каждая программа из code/ собирается avr-gcc под ATmega16 двумя наборами флагов: `-Os -Wall -Wextra` и то же с флагами AVR Studio 4 по умолчанию (`-std=gnu99 -funsigned-char -funsigned-bitfields -fpack-struct -fshort-enums`). Требование: 0 ошибок и 0 предупреждений, программа влезает во flash (16 КБ) и в RAM (1 КБ).
2. **Логика на ПК** ([tests/logic.sh](tests/logic.sh), модель в [tests/sim.h](tests/sim.h)). Программы собираются обычным gcc, регистры и таймеры подменены моделью: кнопки нажимаются с дребезгом, клавиатура моделируется матрицей, проверяются переносы, полночь, частотомер, ШИМ. Мутанты (копии программ с намеренно внесённой типичной ошибкой, tests/mutants/) показывают, что тест эту ошибку ловит.
3. **Тексты** ([tests/check_docs.py](tests/check_docs.py)). Фрагменты «Пишем вместе» дословно совпадают с полными файлами; ссылки и якоря ведут куда надо; спойлеры оформлены так, что GitHub их отрисует; в программах только ASCII и кириллица (иначе zip в Windows-1251 не соберётся); блок ПОДКЛЮЧЕНИЕ каждой программы укладывается в 16 гнёзд панели.

Нужны avr-gcc, gcc и python3. В Ubuntu и Debian:

```
sudo apt-get install gcc-avr avr-libc binutils-avr gcc python3
```

Если avr-gcc не установлен, а docker есть, run.sh соберёт всё в контейнерах: alpine:3.20 для avr-gcc, gcc:13 для логики. Переменные: `MODE=native` или `MODE=docker` (выбрать режим явно), `AVR_BIN=папка с avr-gcc` (несколько папок через двоеточие: собрать каждым компилятором), `CC=gcc`. Полный лог: `sh tests/run.sh 2>&1 | tee run.log`.

На каждый push и pull request то же самое запускает GitHub Actions ([ci.yml](.github/workflows/ci.yml)). Тег вида `v1.0` запускает [release.yml](.github/workflows/release.yml): проверки, сборка zip в Windows-1251 ([tools/make_zip.py](tools/make_zip.py)) и релиз с этим zip. Собрать zip вручную: `python3 tools/make_zip.py v1.0`, он появится в папке dist/.

## Структура репозитория

```
README.md                этот файл
LICENSE                  лицензия MIT на программы и скрипты (тексты под CC BY 4.0)
docs/                    главы 1–12 и справка
code/NN-тема/            программы по главам: UTF-8, LF, шапка с блоком ПОДКЛЮЧЕНИЕ
tests/run.sh             все проверки одной командой
tests/build.sh           сборка avr-gcc двумя наборами флагов, размеры flash и RAM
tests/prepare.py         копии программ для тестов на ПК (в tests/.work/) и мутанты
tests/logic.sh, sim.h    тесты логики на ПК: модель регистров, таймеров, кнопок,
tests/stub/, logic/        клавиатуры и индикатора; сами тесты в tests/logic/,
tests/mutants/             мутанты в tests/mutants/
tests/check_docs.py      проверки текстов и шапок программ
tools/make_zip.py        zip в Windows-1251 для AVR Studio 4
.github/workflows/       ci.yml: проверки на каждый push; release.yml: zip к релизу по тегу v*
```
