# 9. счётчик нажатий и дребезг

Те же четыре разряда, что в часах, только такт даёт не таймер, а кнопка: нажали, и число увеличилось на 1, до 9999. Кнопку читаем **опросом** регистра PINC в прерывании Timer0. Внешние прерывания INT0 и INT1 здесь не годятся: их выводы PD2 и PD3 заняты сегментами. Кнопка на внешнем прерывании INT2 и почему ей мешает дребезг: [глава 6](06-preryvaniya.md#внешние-прерывания-int0-int1-int2).

Что должно получиться: одно нажатие даёт ровно +1, удержание кнопки тоже +1, после 9999 идёт 0000. И должно стать понятно, почему «в лоб» так не выходит.

## Подключение

| Что | Куда (гнездо «Контроллера ПУ») | Активный уровень |
|---|---|---|
| сегменты a–g, dp | PD0–PD7 | 1 = горит |
| разряды 1–4 (`Ind[0]`–`Ind[3]`) | PB4–PB7 | 0 = разряд включён |
| кнопка 1 блока «Кнопки» «Контроллера ПУ» | PC1 | нажата = 0, нужна подтяжка |

Гнёзд занято: 13 из 16. Общий провод «Контроллера ПУ» и модуля периферии соединить (см. [Общий провод](01-oborudovanie.md#общий-провод)).

Кнопка на стенде при нажатии замыкает своё гнездо на общий провод через 470 Ом, а отпущенная никуда его не тянет. Поэтому вход PC1 настраивается с подтяжкой: `DDRC=0x00` (вход) и `PORTC=0x02` (подтяжка на PC1). Тогда отпущена = 1, нажата = 0. Подробно: [Подтяжка и бит PUD](04-porty.md#подтяжка-и-бит-pud). Защиты от дребезга у кнопок стенда нет, это часть задачи.

Вместо кнопки на PC1 можно подать медленный импульсный сигнал. Если на столе есть модуль логического анализатора, подойдёт его генератор 1 Гц (земли модулей соединить): программа шага 3 будет прибавлять 1 в секунду. Генератор 1 кГц опросом раз в 2 мс не посчитать, для него нужен частотомер из [главы 11](11-signaly.md).

## Пишем вместе

Сначала делаем «в лоб» и видим, что одно нажатие считается много раз. Потом исправляем в два приёма.

### Шаг 1. Опрос «в лоб»

Берём программу после шага 3 главы 5, [shag3.c](../code/05-indikator/shag3.c) (индикация и полный `kod7`), и сохраняем как новый проект. Обработчик Timer1 в ней оставляем пустым: прерывание Timer1 в `main()` разрешено, и без обработчика программа перезапускалась бы раз в секунду. Добавляем цифры и `show()`, подтяжку на PC1, а в прерывании Timer0 проверяем кнопку: нажата, значит, прибавить.

<!-- фрагмент: ../code/09-knopka/shag1.c -->
```c
// над обработчиками:
unsigned char t1=0, t2=0, t3=0, t4=0;   // цифры счётчика: t1 - единицы, t2 - десятки,
                                        //                t3 - сотни, t4 - тысячи
void show(void)                         // вывести цифры t4 t3 t2 t1 слева направо
{
Ind[0]=kod7[t4];                        // левый разряд: тысячи
Ind[1]=kod7[t3];                        // сотни
Ind[2]=kod7[t2];                        // десятки
Ind[3]=kod7[t1];                        // правый разряд: единицы
}

// в main():
DDRC=0x00;                              // порт C - вход
PORTC=0x02;                             // подтяжка на PC1: отпущена = 1, нажата = 0
// и вместо проверочной строки Ind[0]=kod7[4]; ... :
show();                                 // на старте 0000

// в конец ISR(TIMER0_OVF_vect):
if((PINC & 0x02)==0)                    // PC1 = 0 - кнопка нажата
{
  t1++; if(t1==10){t1=0;}               // пока только единицы, без переносов
  show();                               // показать
}
```

**Проверка:** нажмите один раз коротко: цифра пролетает несколько значений. Прерывание идёт каждые 2 мс, а палец держит кнопку около 150 мс. Каждый опрос, пока кнопка нажата, даёт +1, и ещё добавляет дребезг.

Полный код после шага: [shag1.c](../code/09-knopka/shag1.c)

### Шаг 2. Пауза и перенос до 9999

После нажатия 0,6 с не смотрим на кнопку. Прибавление с переносами выносим в функцию `inc()`. Переносы здесь на 10 во всех разрядах: это уже не время, а число.

<!-- фрагмент: ../code/09-knopka/shag2.c -->
```c
// над обработчиками:
short i2=0;                             // пауза после нажатия, в тиках Timer0 (по 2 мс)

void inc(void)                          // +1 к числу на индикаторе, до 9999
{
t1++;                                   // единицы
if(t1==10){t1=0; t2++;                  // 10 единиц -> +1 десяток
  if(t2==10){t2=0; t3++;                // 10 десятков -> +1 сотня
    if(t3==10){t3=0; t4++;              // 10 сотен -> +1 тысяча
      if(t4==10){t4=0;}}}}              // после 9999 - снова 0000 (}}} закрывают три if выше)
show();                                 // показать новое число
}

// в ISR(TIMER0_OVF_vect) вместо блока из шага 1:
if(i2!=0){i2--;}                        // идёт пауза - кнопку не смотрим
else if((PINC & 0x02)==0)               // паузы нет и кнопка нажата
{
  i2=300;                               // пауза 300 x 2,048 мс = 0,6 с
  inc();                                // +1
}
```

`inc()` вызывает `show()`, поэтому стоит ниже неё.

**Проверка:** одно короткое нажатие = +1. Но если держать кнопку, счёт растёт раз в 0,6 с.

Полный код после шага: [shag2.c](../code/09-knopka/shag2.c)

### Шаг 3. Ловим момент нажатия

Запоминаем прошлое состояние кнопки и считаем только переход «была отпущена, стала нажата». После любого изменения 20 мс кнопку не смотрим: за это время дребезг заканчивается.

<!-- фрагмент: ../code/09-knopka/shag3.c -->
```c
// над обработчиками:
unsigned char prev=0x02;                // прошлое состояние кнопки: 0x02 - отпущена, 0 - нажата

// первой строкой внутри ISR(TIMER0_OVF_vect):
unsigned char k;                        // текущее состояние кнопки

// в ISR(TIMER0_OVF_vect) вместо блока из шага 2:
if(i2!=0){i2--;}                        // идёт пауза - ждём, пока закончится дребезг
else
{
  k = PINC & 0x02;                      // читаем кнопку: 0x02 - отпущена, 0 - нажата
  if(k != prev)                         // состояние изменилось?
  {
    i2=10;                              // 20 мс не смотрим на кнопку (дребезг)
    if(k==0){inc();}                    // было отпущено, стало нажато - это нажатие: +1
    prev = k;                           // запоминаем новое состояние
  }
}
```

Пауза ставится и при нажатии, и при отпускании. Поэтому отскоки при отпускании тоже не дают ложных нажатий.

**Проверка:** 20 нажатий дают ровно 0020, удержание даёт +1. Чтобы не нажимать 9999 раз ради перехода 9999 → 0000, временно задайте старт 9998: в `main()` перед `show();` допишите `t4=9; t3=9; t2=9; t1=8;`.

Полный код после шага: [shag3.c](../code/09-knopka/shag3.c)

### Задание 1. Сравните 555.c и Knopka.c

[Knopka.c](../code/09-knopka/Knopka.c) и [555.c](../code/09-knopka/555.c): счётчики нажатий, которые написал преподаватель. Массивы называются `VD`, `VD_Ypr`, `Kod7`, как в Shasi.c из [главы 8](08-chasy.md). Впишите в `Kod7` свои коды цифр и прошейте обе программы по очереди. Одна из них работает ненадёжно. Найдите разницу в коде и объясните, откуда берётся сбой.

<details>
<summary>Ответ</summary>

В 555.c нет строки `DDRC=0x00, PORTC=0x02;`, то есть не включена подтяжка на PC1 (входом вывод и так стоит после сброса). Отпущенная кнопка оставляет вход «в воздухе», он ловит наводки и читается то 0, то 1: счётчик тикает сам или от поднесённой руки. В Knopka.c подтяжка есть, и в покое на входе стабильная 1.

Насколько сильно сбоит 555.c, зависит от стенда и проводов: иногда висящий вход держится почти стабильно, и разницу видно не сразу. Чтобы увидеть её наверняка, отсоедините провод от кнопки или дотроньтесь до него пальцем.

</details>

### Задание 2. Пауза i2 в Knopka.c

В Knopka.c с дребезгом борется переменная `i2`. Один её шаг = одно переполнение Timer0.

1. Сколько миллисекунд длится пауза `i2=300`?
2. Поставьте `i2=0`, потом `i2=30`. Что происходит со счётом?
3. Что будет, если держать кнопку нажатой? Почему?

<details>
<summary>Ответ</summary>

1. 300 × 2,048 мс ≈ 614 мс, то есть около 0,6 с.
2. `i2=0`: паузы нет, кнопка опрашивается каждые 2 мс, и одно нажатие (~150 мс) насчитывает около 70 единиц. `i2=30`: пауза около 61 мс. Дребезг отфильтрован, но обычное нажатие даёт 2–3 единицы, а при удержании счёт бежит примерно 16 раз в секунду.
3. С `i2=300` счёт растёт раз в 0,6 с: после паузы кнопка снова читается как нажатая. Программа реагирует на **уровень** 0, а не на момент нажатия.

</details>

### Задание 3. Переделайте Knopka.c

Сделайте в Knopka.c то же, что в шаге 3: удержание кнопки должно давать ровно +1. Проверка: 20 нажатий дают ровно 0020, после 9999 идёт 0000.

<details>
<summary>Ответ</summary>

Две правки. К переменным добавьте строку `prev`, а в `ISR(TIMER0_OVF_vect)` всё от строки `if(i2!=0x000)` до конца обработчика (включая `}}}`) замените на блок ниже. Пауза теперь 20 мс и ставится после любого изменения кнопки, а прибавляет только переход в «нажата».

<!-- фрагмент: ../code/09-knopka/edge.c -->
```c
// к переменным:
unsigned char prev=0x02;                // НОВОЕ: прошлое состояние PC1: 0x02 - отпущена, 0 - нажата

// в ISR(TIMER0_OVF_vect) от строки if(i2!=0x000) до конца:
if(i2!=0x000) {i2--;}                   // идёт пауза - ждём, пока закончится дребезг
else {                                  // паузы нет - смотрим на кнопку
  In_Kn = PINC & 0x02;                  // текущее состояние PC1: 0x02 - отпущена, 0 - нажата
  if(In_Kn != prev)                     // НОВОЕ: состояние изменилось?
  {
    i2=10;                              // НОВОЕ: 10 x 2,048 мс = 20 мс не смотрим на кнопку
    if(In_Kn==0x00)                     // стало "нажата": это момент нажатия, +1
    {
      t1++;                             // +1 к единицам
      if(t1==10) {t1=0; t2++;           // перенос в десятки
        if(t2==10) {t2=0; t3++;         // перенос в сотни
          if(t3==10) {t3=0; t4++;       // перенос в тысячи
            if(t4==10) {t4=0;}}}}       // после 9999 - снова 0000 (}}} закрывают три if выше)
      VD[3]=Kod7[t1];                   // единицы
      VD[2]=Kod7[t2];                   // десятки
      VD[1]=Kod7[t3];                   // сотни
      VD[0]=Kod7[t4];                   // тысячи
    }
    prev = In_Kn;                       // НОВОЕ: запоминаем новое состояние
  }
}
}
```

Полная программа: [edge.c](../code/09-knopka/edge.c). В ней `Kod7` уже заполнен.

</details>

### Задание 4. Для тех, кто успел

1. PC0 сбрасывает счётчик в 0000 (подтяжку на PC0 не забудьте).
2. PC0 уменьшает счёт на 1, после 0000 идёт 9999.
3. Объединить с часами из главы 8: часы идут сами, кнопка PC1 добавляет минуту.
4. Секундомер MM:SS: PC1 запускает и останавливает, PC0 сбрасывает.

Для пунктов 1, 2 и 4 нужна вторая кнопка:

| Что | Куда (гнездо «Контроллера ПУ») | Активный уровень |
|---|---|---|
| сегменты a–g, dp | PD0–PD7 | 1 = горит |
| разряды 1–4 | PB4–PB7 | 0 = разряд включён |
| кнопка 1 блока «Кнопки» | PC1 | нажата = 0, нужна подтяжка |
| кнопка 2 блока «Кнопки» | PC0 | нажата = 0, нужна подтяжка |

Гнёзд занято: 14 из 16 (в пункте 3 кнопка одна: 13 из 16), общий провод модулей соединён, как выше.

<details>
<summary>Решение 1 и 2: две кнопки</summary>

У каждой кнопки свои «прошлое состояние» и пауза (`prev1`, `w1` и `prev0`, `w0`), обе обрабатываются так же, как в шаге 3. Подтяжка на обоих входах: `PORTC=0x03`.

Отнимать 1 от нуля «в лоб» нельзя: у `unsigned char` 0 − 1 даёт 255. Поэтому сначала проверяем, больше ли цифра нуля, и если нет, ставим 9 и занимаем из следующего разряда:

<!-- фрагмент: ../code/09-knopka/two.c -->
```c
void dec(void)                          // -1 к числу на индикаторе, после 0000 - 9999
{
if(t1>0){t1--;} else {t1=9;             // единицы: из 0 -> 9 и заём из десятков
  if(t2>0){t2--;} else {t2=9;           // десятки: из 0 -> 9 и заём из сотен
    if(t3>0){t3--;} else {t3=9;         // сотни: из 0 -> 9 и заём из тысяч
      if(t4>0){t4--;} else {t4=9;}}}}   // тысячи: из 0 -> 9, то есть 0000 - 1 = 9999
show();                                 // показать новое число
}
```

Сброс вместо вычитания: в обработчике замените `dec();` на `reset();`, функция `reset()` в программе уже есть.

Полная программа: [two.c](../code/09-knopka/two.c)

</details>

<details>
<summary>Решение 3: часы и кнопка «+1 минута»</summary>

Timer1 ведёт часы, как в shag2.c главы 8, а Timer0 крутит индикацию и опрашивает кнопку по схеме шага 3. Нажатие прибавляет минуту, секунды не трогает. Оба обработчика меняют `t1`–`t4`, но конфликта нет: на AVR обработчик не прерывается другим прерыванием, пока сам не вызовет `sei()`.

Полная программа: [clockbtn.c](../code/09-knopka/clockbtn.c)

</details>

<details>
<summary>Решение 4: секундомер</summary>

Старт и стоп делает сам Timer1: биты делителя CS = 0, и таймер стоит, CS12 = 1, и он считает (делитель 256). Так начатая секунда не теряется при паузе. Сброс останавливает таймер и обнуляет и цифры, и `TCNT1`.

<!-- фрагмент: ../code/09-knopka/stopwatch.c -->
```c
void sw_toggle(void)                    // старт/стоп
{
if(TCCR1B & (1<<CS12))                  // таймер сейчас считает?
TCCR1B &= ~(1<<CS12);                   // да - останавливаем (делитель 0)
else
TCCR1B |= (1<<CS12);                    // нет - запускаем (делитель 256)
}
```

Полная программа: [stopwatch.c](../code/09-knopka/stopwatch.c)

</details>

## Дребезг

Механический контакт при замыкании и размыкании несколько раз отскакивает. 1–20 мс на выходе идёт пачка импульсов вместо одного перехода (в лекции для кнопок дана оценка 10–20 мс). Микроконтроллер читает вход за доли микросекунды и видит несколько нажатий. У кнопок стенда аппаратной защиты нет, бороться приходится программой.

Способы борьбы:

| Способ | Как работает | Где в курсе | Недостаток |
|---|---|---|---|
| Пауза после срабатывания | заметили 0, N мс кнопку не смотрим | [Knopka.c](../code/09-knopka/Knopka.c), [shag2.c](../code/09-knopka/shag2.c) | при удержании дольше паузы идёт автоповтор |
| Ловить фронт | помним прошлое состояние, считаем только переход 1 → 0, после любого изменения пауза | [shag3.c](../code/09-knopka/shag3.c), [edge.c](../code/09-knopka/edge.c) | нужна переменная на каждую кнопку |
| Подтверждение | считаем состояние новым, только если оно держится K опросов подряд, например 5 опросов по 2 мс = 10 мс | клавиатура в [главе 10](10-klaviatura.md) (раздел «Антидребезг для клавиатуры»): клавиша засчитывается, когда 4 прохода опроса подряд видно одно и то же | реакция запаздывает на K опросов |
| Аппаратно | RC-цепочка и триггер Шмитта на входе | на стенде нет | лишние детали |

Опрос или внешнее прерывание:

| | Опрос (по таймеру) | Внешнее прерывание |
|---|---|---|
| Выводы | любой | только PD2 (INT0), PD3 (INT1), PB2 (INT2) |
| Дребезг | легко отфильтровать по времени | срабатывает на каждый отскок, прерывание приходится запрещать на время дребезга |
| Реакция | с задержкой до периода опроса (здесь 2 мс) | сразу |
| Когда брать | кнопки, клавиатуры, медленные сигналы | короткие импульсы, пробуждение из сна, счёт быстрых событий |

На этом стенде с четырьмя разрядами свободен только INT2 (PB2): PD2 и PD3 заняты сегментами. Регистры внешних прерываний: [Внешние прерывания INT0, INT1, INT2](06-preryvaniya.md#внешние-прерывания-int0-int1-int2).

## Вопросы для самопроверки

1. Зачем `PORTC=0x02`, если `DDRC=0x00`? Что прочитается с PC1 без этой строки?
2. Зачем маска `& 0x02` после чтения PINC?
3. Опрос или внешнее прерывание: когда что удобнее?
4. Почему в шаге 3 пауза ставится и при нажатии, и при отпускании?
5. Кнопку перенесли на PB2 (вход с подтяжкой), а развёртка индикатора пишет `PORTB=Mas[i1];` с масками {0xE0, 0xD0, 0xB0, 0x70}. Почему кнопка начала «нажиматься» сама?
6. В каком регистре ATmega16 бит PUD и чему он равен после сброса?

<details>
<summary>Ответы</summary>

1. Если вывод настроен на вход, единица в его бите PORT включает встроенный подтягивающий резистор. Без неё отпущенная кнопка оставляет PC1 «в воздухе», и чтение случайно.
2. PINC отдаёт сразу 8 битов порта C, остальные выводы могут быть в любом состоянии (на этом стенде PC2–PC5 заняты JTAG). Маска оставляет только бит PC1, и сравнение с 0 проверяет одну кнопку.
3. Для кнопок с дребезгом опрос по таймеру проще и надёжнее. Внешнее прерывание нужно для коротких быстрых импульсов, которые опрос раз в 2 мс пропустит. На этом стенде INT0 и INT1 к тому же заняты сегментами (PD2, PD3).
4. При отпускании контакт тоже дребезжит. Без паузы отскоки отпускания выглядели бы как новые переходы «отпущена → нажата», и одно нажатие давало бы лишние единицы.
5. Запись целого байта меняет все 8 битов порта. В масках бит PB2 равен 0, а у входа бит PORTB2 управляет подтяжкой: 0 её выключает, и вход повисает. Нужны маски с единицей в бите PB2 (0xE4, 0xD4, 0xB4, 0x74) и гашение `PORTB=0xF4;`, как в частотомере [главы 11](11-signaly.md).
6. В SFIOR (бит 2). После сброса PUD = 0, подтяжки разрешены, специально его сбрасывать не нужно.

</details>
