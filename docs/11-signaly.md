# 11. Внешние сигналы и ШИМ

Три программы на внешние сигналы. Частотомер принимает сигнал снаружи: внешнее прерывание INT2 считает фронты, Timer1 отмеряет окно 1 с. Яркость светодиода выдаёт сигнал наружу: Timer0 сам формирует ШИМ на своём выводе. Пищалка (по желанию) звучит от меандра, который делает Timer2.

Что должно получиться: частотомер показывает частоту своего же меандра 488 Гц, светодиод меняет яркость шагами по 10 % от настоящего нуля до полной, и вы можете объяснить, откуда берутся 488, 489 и почему 0 % не получается числом OCR0.

Понадобятся: внешние прерывания из [главы 6](06-preryvaniya.md#внешние-прерывания-int0-int1-int2), режимы таймеров и [ШИМ](07-tajmery.md#шим) из главы 7, динамическая индикация из [главы 5](05-indikator.md#динамическая-индикация), антидребезг кнопок из [главы 9](09-knopka.md#дребезг).

## Частотомер

Частота в герцах равна числу периодов за секунду. Программа [freq.c](../code/11-signaly/freq.c) считает фронты сигнала из 0 в 1 ровно 1 с, показывает число и начинает считать заново:

| Что | Чем | Как часто |
|---|---|---|
| считает фронты на PB2 | внешнее прерывание INT2: `cnt++` | на каждый фронт |
| закрывает окно 1 с | Timer1, режим CTC, делитель 256, `OCR1A=31249` | раз в секунду |
| крутит индикацию | Timer0, переполнение | каждые 2,048 мс |
| выдаёт меандр 488 Гц для самопроверки | Timer0 в режиме Fast PWM, выход OC0 = PB3 | сам, без участия программы |

| Что | Куда (гнездо «Контроллера ПУ») | Активный уровень |
|---|---|---|
| сегменты a–g, dp | PD0–PD7 | 1 = горит |
| разряды 1–4 (`Ind[0]`–`Ind[3]`) | PB4–PB7 | 0 = разряд включён |
| измеряемый сигнал | PB2 (вход INT2) | считаются фронты из 0 в 1 |
| перемычка для самопроверки | PB3 (выход OC0), второй конец в PB2 | меандр 488 Гц |

Гнёзд занято: 14 из 16. Общий провод «Контроллера ПУ» и модуля периферии соединить, а если сигнал идёт с другого модуля, то и с ним (см. [Общий провод](01-oborudovanie.md#общий-провод)). На вход только сигналы с уровнями 0 и 5 В.

Из трёх внешних прерываний свободен только INT2: выводы INT0 и INT1 (PD2, PD3) заняты сегментами. Если `Ind[0]` у вас справа и маски переставлены, как в [главе 8](08-chasy.md), переставьте их и здесь: `{0x74,0xB4,0xD4,0xE4}`.

### Как работает freq.c

Два коротких обработчика:

<!-- фрагмент: ../code/11-signaly/freq.c -->
```c
ISR(INT2_vect)                          // фронт из 0 в 1 на PB2: +1
{
if(cnt<10000){cnt++;}                   // дальше 10000 не считаем - всё равно "----"
}
ISR(TIMER1_COMPA_vect)                  // ровно раз в секунду: окно закрылось
{
show_num(cnt);                          // сколько фронтов пришло за секунду = частота, Гц
cnt=0;                                  // начинаем новую секунду
}
```

Настройка INT2 в `main()`:

<!-- фрагмент: ../code/11-signaly/freq.c -->
```c
MCUCSR|= (1<<ISC2);                     // INT2 по фронту из 0 в 1
GIFR = (1<<INTF2);                      // смена ISC2 могла поставить флаг - сбрасываем (записью 1)
GICR|= (1<<INT2);                       // разрешаем прерывание INT2
```

Смена бита ISC2 сама может поставить флаг INTF2, тогда сразу после `sei()` придёт лишнее прерывание. Поэтому флаг сбрасывают записью 1 и только потом разрешают INT2. Регистры: [Внешние прерывания INT0, INT1, INT2](06-preryvaniya.md#внешние-прерывания-int0-int1-int2).

Окно: 8 000 000 / 256 = 31 250 тиков Timer1 в секунду, счёт 0..31249 занимает ровно 31 250 тиков, то есть ровно 1 с. Числа для других окон: [Таймерные числа при 8 МГц](spravka.md#таймерные-числа-при-8-мгц).

На PB2 включена подтяжка. Без сигнала вход стоит в 1 и не ловит наводки, а источником может быть даже кнопка, которая тянет вход к общему проводу. Развёртка пишет PORTB целиком, поэтому в масках и в `PORTB=0xF4` бит PB2 равен 1:

<!-- фрагмент: ../code/11-signaly/freq.c -->
```c
char Mas[4]={0xE4,0xD4,0xB4,0x74};      // маски разрядов {PB4..PB7} + подтяжка PB2 (бит 0x04)
```

Это та же ловушка, что в варианте Б клавиатуры ([глава 10](10-klaviatura.md)) и в задании 5 [главы 4](04-porty.md): ноль в бите PB2 выключает подтяжку, и вход начинает считать наводки.

### Свой меандр 488 Гц на PB3

Внешнего генератора на столе может не быть, поэтому программа делает сигнал сама. Timer0 и так крутит индикацию; переводим его в режим Fast PWM и подключаем вывод OC0 (PB3):

<!-- фрагмент: ../code/11-signaly/freq.c -->
```c
OCR0=127;                               // меандр на OC0: 128 тиков из 256 единица, 128 ноль
TCCR0|= (1<<WGM01)|(1<<WGM00);          // Timer0: режим Fast PWM, счёт 0..255 по кругу, как в Normal
TCCR0|= (1<<COM01);                     // выход OC0 (PB3): 1 с начала периода, 0 после совпадения с OCR0
TCCR0|= (1<<CS01)|(1<<CS00);            // Timer0: делитель 64 - пошёл счёт: 8 МГц / 64 / 256 = 488 Гц
```

В режиме Fast PWM Timer0 считает 0..255 по кругу, как и в Normal, и прерывание переполнения приходит так же, каждые 2,048 мс: индикация не замечает разницы. Заодно таймер сам ставит PB3 в 1 в начале каждого круга и сбрасывает в 0 при совпадении с OCR0 = 127. Получается меандр 8 000 000 / 64 / 256 = 488,28 Гц. Перемычка PB3–PB2, и частотомер меряет сам себя.

Подробно про режимы и COM-биты: [ШИМ](07-tajmery.md#шим), какие выходы таймеров есть на панели: [Выводы таймеров на панели](07-tajmery.md#выводы-таймеров-на-панели).

### Откуда взять сигнал

| Источник | Как подключить | Что покажет |
|---|---|---|
| свой меандр с PB3 | перемычка PB3–PB2 | 0488, иногда 0489 |
| генератор 1 Гц модуля логического анализатора | выход генератора в PB2, клемма общего провода модуля к общему проводу «Контроллера ПУ» | 0001, изредка 0000 или 0002 |
| генератор 1 кГц того же модуля | так же | около 1000 |
| второй «Контроллер ПУ» с freq.c | его PB3 в наш PB2, общие провода соединить | 0488, иногда 0489 |
| второй «Контроллер ПУ» с zvuk.c | его PD7 в наш PB2, держать его кнопку | 1000 (±1) |
| кнопка «Контроллера ПУ» | гнездо кнопки в PB2 | сколько фронтов дало одно нажатие |

Модуль логического анализатора входит в комплект стенда ИПУ, но есть ли он у вас на столе, не подтверждено. После подключения к USB модуль выключен: коснитесь сенсора питания и держите около 3 с, светодиод питания плавно разгорится, мигнёт и останется гореть (подробнее в [главе 1](01-oborudovanie.md)). Затем включите нужный генератор касанием его сенсора «Вкл./Выкл.» (загорится светодиод генератора); выключенный генератор держит на выходе 0. Амплитуда 5 В, выходы через 470 Ом. Насколько точны его 1 кГц, в описании не сказано.

Модулей «Контроллер ПУ» в комплекте два. Второй прошивается так же, как первый ([Прошивка через JTAG ICE](02-avr-studio.md#прошивка-через-jtag-ice)), и становится генератором с кварцевой точностью.

### Точность и пределы

- **±1 за окно.** Окно и сигнал друг о друге не знают. За секунду укладывается 488,28 периода меандра, а посчитать можно только целое число фронтов: 488 или 489, смотря куда попал первый. 489 будет примерно в каждом четвёртом окне. Для 1 Гц то же самое: обычно в окно попадает один фронт, а когда фронт совпадает с границей окна, бывает 0 или 2.
- **Сверху 9999 Гц**: больше не помещается в четыре разряда, горит «----».
- **Потеря фронтов выше примерно 7 кГц.** Обработчик Timer1 раскладывает число на цифры (`show_num`, пять делений по 16 бит) и занимает около 0,14 мс (примерно 1100 тактов). В это время INT2 ждёт, а флаг INTF2 помнит только один фронт. Если за 0,14 мс приходят два фронта (частота выше примерно 7 кГц), один теряется, и показание может быть на 1 меньше. Лечится так: считать в INT2 сразу десятичными цифрами, как счётчик из главы 9, или делить в основном цикле, а не в прерывании.
- **Снизу 1 Гц**: это шаг показаний. Для медленных сигналов правильнее мерить не число периодов, а длительность периода (у Timer1 для этого есть захват на ICP1 = PD6, но здесь PD6 занят сегментом).
- **Уровни.** На входе 0 должен быть ниже примерно 1 В, 1 выше примерно 3 В (0,2 и 0,6 от питания 5 В по документации на ATmega16). Сигналы выше 5 В и ниже 0 на гнёзда не подавать.

## Яркость светодиода: ШИМ

Светодиод включается и выключается 488 раз в секунду. Глаз не видит мигания и воспринимает среднюю яркость: чем большую долю периода светодиод горит, тем он ярче. Долю задаёт число OCR0, а включает и выключает вывод сам Timer0, программа только меняет число. Теория ШИМ: [ШИМ](07-tajmery.md#шим).

| Что | Куда (гнездо «Контроллера ПУ») | Активный уровень |
|---|---|---|
| сегменты a–g, dp | PD0–PD7 | 1 = горит |
| разряды 1–4 (`Ind[0]`–`Ind[3]`) | PB4–PB7 | 0 = разряд включён |
| светодиод блока «Светодиоды» «Контроллера ПУ» (любое из четырёх гнёзд блока) | PB3 (выход OC0) | 0 = горит |
| кнопка «ярче» блока «Кнопки» | PC1 | нажата = 0, нужна подтяжка |
| кнопка «тусклее» блока «Кнопки» | PC0 | нажата = 0, нужна подтяжка |

Гнёзд занято: 15 из 16. Общий провод «Контроллера ПУ» и модуля периферии соединить.

Почему PB3: это OC0, единственный выход ШИМ на панели, не занятый индикатором (OC1A = PD5, OC1B = PD4 и OC2 = PD7 здесь сегменты). Программа: [pwm.c](../code/11-signaly/pwm.c). PC1 прибавляет 10 %, PC0 убавляет, на индикаторе проценты. Если `Ind[0]` у вас справа и маски переставлены, как в [главе 8](08-chasy.md), здесь они будут `{0x78,0xB8,0xD8,0xE8}`.

### Как работает pwm.c

Timer0 настроен на инверсный Fast PWM:

| Биты TCCR0 | Что задают |
|---|---|
| WGM01 = 1, WGM00 = 1 | режим Fast PWM: счёт 0..255 по кругу, переполнение каждые 2,048 мс, как в Normal |
| COM01 = 1, COM00 = 1 | инверсный ШИМ: от начала круга до совпадения с OCR0 на PB3 0, потом 1 |
| CS01 = 1, CS00 = 1 | делитель 64: 8 000 000 / 64 / 256 = 488 Гц |

Вместе `TCCR0 = 0x7B`. Инверсный, потому что светодиод «Контроллера ПУ» горит от 0: он горит (OCR0 + 1)/256 периода, и чем больше OCR0, тем ярче. Числа для шагов по 10 % взяты так, чтобы доля была как можно ближе к круглым процентам:

| Яркость | OCR0 | Горит, доля периода |
|---|---|---|
| 0 % | OC0 отключён, на PB3 1 | 0 |
| 10 % | 25 | 26/256 = 10,2 % |
| 20 % | 50 | 51/256 = 19,9 % |
| 30 % | 76 | 77/256 = 30,1 % |
| 40 % | 101 | 102/256 = 39,8 % |
| 50 % | 127 | 128/256 = 50,0 % |
| 60 % | 153 | 154/256 = 60,2 % |
| 70 % | 178 | 179/256 = 69,9 % |
| 80 % | 204 | 205/256 = 80,1 % |
| 90 % | 229 | 230/256 = 89,8 % |
| 100 % | 255 | весь период: на выходе всё время 0 |

### Крайние значения OCR0

У Fast PWM крайние значения несимметричны. OCR0 = 255 даёт на выходе постоянный уровень, здесь постоянный 0, и светодиод горит полностью. А OCR0 = 0 не даёт постоянной 1: в начале каждого круга вывод всё равно на один тик (8 мкс из 2,048 мс) уходит в 0. Это 1/256 периода, около 0,4 %: светодиод слабо, но заметно светится, особенно в полутьме.

Поэтому для 0 % pwm.c не пишет OCR0 = 0, а отключает выход таймера от вывода:

<!-- фрагмент: ../code/11-signaly/pwm.c -->
```c
void set_level(void)                    // применить яркость и показать её
{
if(level==0)                            // 0 %:
{
  TCCR0&=~((1<<COM01)|(1<<COM00));      // отключаем OC0 от вывода: на PB3 бит PORTB = 1, не горит
}
else                                    // 10..100 %:
{
  OCR0=pwm[level];                      // горит (OCR0+1)/256 периода
  TCCR0|= (1<<COM01)|(1<<COM00);        // подключаем OC0: инверсный ШИМ на PB3
}
Ind[0]=0x00;                            // разряд тысяч пустой
Ind[1]=(level==10) ? kod7[1] : 0x00;    // "1" только для 100 %
Ind[2]=(level==0)  ? 0x00 : kod7[level%10];  // десятки процентов (для 0 % - пусто)
Ind[3]=kod7[0];                         // единицы процентов всегда 0
}
```

Когда COM01 = COM00 = 0, PB3 становится обычным выходом порта, и на нём то, что записано в бит 3 PORTB. Развёртка индикатора пишет PORTB целиком, поэтому в масках и в `PORTB=0xF8` бит PB3 равен 1 (светодиод не горит):

<!-- фрагмент: ../code/11-signaly/pwm.c -->
```c
char Mas[4]={0xE8,0xD8,0xB8,0x78};      // маски разрядов {PB4..PB7} + PB3 = 1 (бит 0x08): на 0 % не горит
```

Пока выход OC0 подключён, этот бит ни на что не влияет, выводом управляет таймер. Ловушка та же, что с подтяжками в [главе 10](10-klaviatura.md): забытая единица в бите PORTB.

Ещё две детали:

- OCR0 в режимах ШИМ буферизован: новое число вступает в силу с начала следующего круга, поэтому смена яркости не даёт рывков на середине периода.
- Кнопки читаются в том же прерывании Timer0, с паузой 20 мс после каждого изменения, как в [главе 9](09-knopka.md#дребезг): одно нажатие, даже с удержанием, даёт один шаг.

Если ваш светодиод горит от 1 (светодиоды модуля периферии не проверены), нужен прямой ШИМ: в `set_level()` уберите `(1<<COM00)`, а в масках и обеих строках `PORTB=0xF8` сделайте бит PB3 нулём (0xE0, 0xD0, 0xB0, 0x70 и 0xF0).

<details>
<summary>Ответ</summary>

Нужны не равные прибавки, а равные отношения: каждый шаг ярче предыдущего примерно в одно и то же число раз (здесь примерно в 1,85). Например:

```c
const unsigned char pwm[11]={0,0,1,2,5,11,21,39,74,137,255};  // шаги примерно x1,85 (OCR0+1)
```

Доли получаются 0,4 %, 0,8 %, 1,2 %, 2,3 %, 4,7 %, 8,6 %, 15,6 %, 29,3 %, 53,9 %, 100 %. Индикатор теперь показывает номер ступени (×10), а не процент. Такую поправку на глаз называют гамма-коррекцией.

</details>

## Пищалка (по желанию)

На модуле периферии есть пьезоизлучатель. Что о нём неизвестно: как подписано его гнездо, какой он, пассивный (звучит только от меандра) или активный (пищит сам от постоянного уровня), и каким уровнем включается. В описании модуля есть лабораторная «музыкальная шкатулка», так что, скорее всего, он пассивный, но это не проверено.

Программа [zvuk.c](../code/11-signaly/zvuk.c): пока нажата кнопка PC1, на PD7 меандр 1000 Гц.

| Что | Куда (гнездо «Контроллера ПУ») | Активный уровень |
|---|---|---|
| вход пищалки модуля периферии | PD7 (выход OC2) | меандр; уровень включения неизвестен |
| кнопка блока «Кнопки» «Контроллера ПУ» | PC1 | нажата = 0, нужна подтяжка |

Гнёзд занято: 2 из 16. Общий провод «Контроллера ПУ» и модуля периферии соединить. Индикатор для этой программы не нужен.

Звук делает Timer2 в режиме CTC: при каждом совпадении счёта с OCR2 он сам переключает вывод OC2 (PD7). Настройка в `main()`:

<!-- фрагмент: ../code/11-signaly/zvuk.c -->
```c
OCR2=124;                               // Timer2 считает 0..124: 125 тиков по 4 мкс = 0,5 мс
TCCR2|= (1<<WGM21);                     // Timer2: режим CTC (сброс при TCNT2==OCR2)
TCCR2|= (1<<CS21)|(1<<CS20);            // Timer2: делитель 32 (у Timer2 код 011 - это 32, у Timer0 - 64)
```

Программа только подключает выход таймера к выводу, пока кнопка нажата. Кнопку раз в 2,048 мс смотрит обработчик Timer0:

<!-- фрагмент: ../code/11-signaly/zvuk.c -->
```c
ISR(TIMER0_OVF_vect)                    // каждые 2,048 мс: смотрим на кнопку
{
if(!(PINC & (1<<PC1)))                  // кнопка нажата (на PC1 0)
{
  TCCR2|= (1<<COM20);                   // подключаем OC2: таймер сам переключает PD7 - звук
}
else                                    // кнопка отпущена
{
  TCCR2&=~(1<<COM20);                   // отключаем OC2: на PD7 снова бит PORTD - тишина
}
}
```

Частота: 8 000 000 / (2 × 32 × (1 + 124)) = 1000 Гц ровно (двойка потому, что период состоит из двух переключений; формула CTC: [Формулы](07-tajmery.md#формулы)). С Timer0 ровно 1000 Гц не получить: у него нет делителя 32, а с 64 нужен OCR0 = 61,5. Обратите внимание на биты делителя: у Timer2 код 011 (CS21, CS20) означает 32, а у Timer0 тот же код означает 64. Таблица делителей Timer2: [Timer2 и асинхронный режим](07-tajmery.md#timer2-и-асинхронный-режим).

Как понять, какая у вас пищалка:

- Без нажатия тихо, с нажатием чистый тон: пассивная, всё правильно.
- Пищит без нажатия: активная, и включается она уровнем покоя PD7 (в программе 0). Поставьте в `main()` `PORTD=0x80;` (в покое 1).
- С нажатием хриплый, дребезжащий звук, а при одном из уровней покоя громкий писк своим тоном: активная. Ей меандр не нужен, включайте её постоянным уровнем, как светодиод.

### Задание 7. Другая высота тона

Подключение: таблица выше, гнёзд 2 из 16. Сделайте тон 2000 Гц, потом ноту «ля» первой октавы, 440 Гц.

<details>
<summary>Ответ</summary>

f = 8 000 000 / (2 × N × (1 + OCR2)), то есть OCR2 = 8 000 000 / (2 × N × f) − 1, и OCR2 должен быть целым и не больше 255.

- 2000 Гц: с делителем 32 выходит OCR2 = 61,5, не целое. С делителем 8 ровно: `OCR2=249;` и вместо строки с CS21, CS20 `TCCR2|= (1<<CS21);` (у Timer2 код 010 = 8).
- 440 Гц: с делителем 32 нужен OCR2 = 283, в 8 бит не влезает. С делителем 64: OCR2 = 141, получится 440,1 Гц. У Timer2 делитель 64 задаёт код 100: `TCCR2|= (1<<CS22);`, а не CS21 и CS20, как у Timer0.

Проверить высоту можно частотомером на втором контроллере (задание 4).

</details>

## Если не работает

| Что видно | Вероятная причина | Что сделать |
|---|---|---|
| частотомер с сигналом показывает 0000 | сигнал не в PB2 (PB3 здесь выход), нет общего провода, не включён модуль анализатора или сам генератор | проверить гнездо, общий провод, светодиоды питания модуля и генератора |
| без сигнала показание «гуляет» | у PB2 нет подтяжки (маски без «\| 0x04») | проверить маски и `PORTB=0xF4` |
| с перемычкой 0000 | перемычка не в тех гнёздах (нужны PB3 и PB2) или в программе не включён выход OC0 | проверить гнёзда и строки `TCCR0` |
| яркость не меняется, светодиод горит или не горит постоянно | светодиод не на PB3, нет подтяжки кнопок | проверить гнездо и `PORTC=0x03` |
| кнопки работают «наоборот», 100 % темнее, чем 10 % | светодиод горит от 1 | прямой ШИМ (см. «Как работает pwm.c») |
| на 0 % светодиод горит полностью | в масках бит PB3 равен 0 | маски с «\| 0x08», `PORTB=0xF8` |
| пищалка молчит | не то гнездо, нет общего провода, пищалка активная | раздел «Пищалка» |

Остальное: [12. Не работает: что проверить](12-ne-rabotaet.md).

## Вопросы для самопроверки

1. Почему частотомер показывает то 488, то 489, а не 488,28?
2. Зачем на PB2 подтяжка и почему в масках freq.c бит 0x04?
3. Почему после `MCUCSR|= (1<<ISC2);` стоит `GIFR = (1<<INTF2);`?
4. Что ограничивает частотомер сверху?
5. Почему индикация не сломалась, когда Timer0 перевели в режим Fast PWM?
6. Почему при OCR0 = 0 светодиод всё равно светится? Как pwm.c получает настоящий 0 %?
7. Зачем в pwm.c в масках бит PB3, если PB3 управляет таймер?
8. Какая частота ШИМ в pwm.c и зависит ли она от яркости?
9. Почему для светодиода «Контроллера ПУ» ШИМ инверсный?
10. Почему в zvuk.c биты делителя CS21 и CS20 дают 32, а не 64?
11. Чем активная пищалка отличается от пассивной?

<details>
<summary>Ответы</summary>

1. Частота меандра 488,28 Гц, а считается целое число фронтов за окно. Окно и сигнал не синхронны, поэтому в окно попадает то 488, то 489 фронтов. Погрешность такого частотомера ±1 за окно.
2. Без сигнала вход должен стоять в известном уровне, иначе он ловит наводки и считает их. С подтяжкой там 1, и источником может быть даже кнопка на общий провод. Развёртка пишет PORTB целиком, бит 0x04 в масках сохраняет 1 в PORTB2, то есть подтяжку.
3. Смена ISC2 может сама поставить флаг INTF2. Без сброса после `sei()` пришло бы лишнее прерывание, и первое окно насчитало бы на 1 больше. Флаг сбрасывается записью 1.
4. Четыре разряда (9999 Гц) и время обработчиков: пока идёт обработчик Timer1 с делениями (около 0,14 мс), INT2 ждёт, а флаг помнит только один фронт. Выше примерно 7 кГц фронт может потеряться.
5. В Fast PWM Timer0 считает 0..255 по кругу, как в Normal, и переполняется так же, каждые 256 тиков (2,048 мс). Прерывание TIMER0_OVF приходит с прежней частотой.
6. В Fast PWM при OCR0 = 0 выход в начале каждого круга один тик стоит в 0, это 1/256 периода. pwm.c на 0 % отключает выход OC0 (COM01 = COM00 = 0), и PB3 становится обычным выходом с 1 из PORTB.
7. Пока OC0 подключён, бит не действует. На 0 % OC0 отключён, и на PB3 появляется то, что в бите 3 PORTB. Развёртка пишет PORTB целиком; без 1 в этом бите светодиод на 0 % горел бы полностью.
8. 8 000 000 / 64 / 256 = 488 Гц. От яркости не зависит: OCR0 меняет только долю периода. На 0 % и 100 % фронтов нет вовсе.
9. Светодиод горит, когда на гнезде 0. В инверсном режиме выход в 0 от начала круга до совпадения, и время свечения (OCR0 + 1)/256 растёт вместе с OCR0.
10. У Timer2 своя таблица делителей: 001 = 1, 010 = 8, 011 = 32, 100 = 64, 101 = 128, 110 = 256, 111 = 1024. У Timer0 код 011 означает 64. Путать нельзя: тон уйдёт вдвое.
11. Пассивная звучит только от переменного сигнала (меандра) и с той частотой, которую ей дали. Активная содержит свой генератор и пищит своим тоном от постоянного уровня. Проверка: zvuk.c, слушать без нажатия и с нажатием при обоих уровнях покоя PD7.

</details>
