# 2. AVR Studio 4: сборка, прошивка, отладка

Программы для «Контроллера ПУ» пишутся и собираются в AVR Studio 4, а прошиваются и отлаживаются через встроенный в модуль JTAG ICE mk1. Более новые среды не подойдут: Atmel Studio 6 и всё, что вышло после неё (Atmel Studio 7, Microchip Studio), JTAG ICE mk1 не поддерживают. Курс рассчитан на AVR Studio 4.19 (build 730), последнюю версию Studio 4, и компилятор из AVR Toolchain 3.4.1 (avr-gcc 4-й серии).

В этой главе: установка, проект на Си, сборка, прошивка, отладка по шагам, русские комментарии (кодировка) и разбор частых ошибок компиляции.

## Установка

Установка по шагам приведена в разделе 4 описания стенда. Курсу нужны три программы, ставьте их в таком порядке:

1. Драйвер FTDI: `CDM20824_Setup.exe` (папка `FTDI_drivers` на диске со стенда). Через него компьютер видит отладчик модуля как COM-порт.
2. AVR Toolchain (компилятор avr-gcc, библиотека avr-libc, make): `avr-toolchain-installer-3.4.1.1195-win32.win32.x86.exe` (папка `AVR_Studio_4`).
3. AVR Studio 4: `AvrStudio4Setup.exe` (та же папка).

Остальное из списка в описании стенда (WinDjView, Adobe Reader, Terminal, LPTprog) курсу не нужно. Программа логического анализатора нужна, только если хотите смотреть сигналы на модуле анализатора. Если папки из описания стенда на диске не нашлось (в описании она местами напечатана как `Sortware`), ищите установщик по имени файла.

Описание стенда предупреждает, что часть программ работает только в 32-разрядной Windows. Studio 4.19 и AVR Toolchain ставятся и в 64-разрядную: компилятор тогда лежит в `C:\Program Files (x86)\Atmel\AVR Tools\AVR Toolchain\bin\` (в 32-разрядной Windows путь тот же, только без `(x86)`). Если драйвер с диска не ставится, скачайте свежий драйвер FTDI VCP с сайта FTDI.

После установки драйвера подключите модуль к компьютеру. В «Диспетчере устройств» (Win+R, `devmgmt.msc`), в разделе «Порты (COM и LPT)», появится новый порт вида USB Serial Port (COM3). Запомните номер: он понадобится, если Studio не найдёт отладчик сама.

## Новый проект

Studio собирает программу только в составе проекта: просто открытый `.c`-файл не собрать. Проект создаёте вы сами. Имя удобно давать по программе, с которой работаете, например `444` для стартовой программы 444.c из [главы 5](05-indikator.md). Здесь проект называется `first`:

1. **Project → Project Wizard → New Project.** Это же окно Studio показывает при запуске.
2. Project type: **AVR GCC**. В описании стенда здесь выбран Atmel AVR Assembler, но это проект на ассемблере, а программы курса написаны на Си.
3. Project name: например, `first`. Галочки Create initial file (создать файл `first.c`) и Create folder (создать папку проекта) оставьте.
4. Location: папка без русских букв и пробелов, например `C:\AVR\`. Studio собирает программу через make, и такие пути её ломают. Рабочий стол и «Документы» не годятся, если имя пользователя Windows русское: путь получится вида `C:\Users\<русское имя>\Desktop`. Все файлы проекта держите в одной папке (так советует и описание стенда).
5. **Next.** Debug platform: **JTAG ICE**. В списке есть ещё JTAGICE mkII: это другой отладчик, нужен JTAG ICE. Device: **ATmega16**.
6. **Finish.** Откроется пустой файл `first.c`: в него вставляют программу (для первого раза см. [«Первая проверка»](#первая-проверка)).
7. **Project → Configuration Options**, страница General: Device `atmega16`, Frequency `8000000` (или пусто, см. ниже), Optimization **-Os**. Галочки Unsigned Chars, Unsigned Bitfields, Pack Structure Members, Short Enums и Create Hex File должны стоять (обычно стоят сразу).

С этими настройками Studio передаёт компилятору ключи `-Wall -gdwarf-2 -Os -std=gnu99 -funsigned-char -funsigned-bitfields -fpack-struct -fshort-enums` (их список виден на странице Custom Options). Что меняет `-funsigned-char`, разобрано в [главе 3](03-si.md#типы-данных-на-avr).

Полезно добавить ключ `-Wextra`: на странице Custom Options слева выберите [All files], впишите `-Wextra` в поле ввода и нажмите Add. Компилятор начнёт предупреждать о большем числе подозрительных мест, например о сравнении `char` с числом больше 127 ([глава 3](03-si.md#типы-данных-на-avr)). Все программы курса собираются с ним без предупреждений.

На той же странице Custom Options указано, где Studio берёт avr-gcc и make; обычно там стоит галочка Use AVR Toolchain. Если сборка обрывается сразу и окно Build пишет, что не найден avr-gcc или make (или `avr-objcopy: 'first.elf': No such file`), Studio не нашла компилятор. Снимите эту галочку и впишите в поля avr-gcc и make полные пути к `avr-gcc.exe` и `make.exe`: оба лежат в папке `AVR Toolchain\bin` ([«Установка»](#установка)).

**Частота.** В каждой программе курса до всех `#include` стоит `#define F_CPU 8000000UL`, поэтому поле Frequency можно оставить пустым: частоту задаёт эта строка. Если компилятор предупреждает `"F_CPU" redefined`, частота задана в двух местах (в коде и в поле Frequency) и записана не одинаково: очистите поле Frequency.

**Optimization.** Если там -O0, программа станет больше, а `_delay_ms()` будет ждать неверное время (компилятор об этом предупредит). Ставьте -Os.

**Платформа отладки.** Её выбирают в мастере (шаг 5), а поменять можно в меню **Debug → Select Platform and Device**. Для сборки и прошивки через Con платформа неважна, но выполнять программу по шагам на стенде можно только с платформой JTAG ICE (про AVR Simulator см. [ниже](#отладка-по-шагам)).

**Готовый файл из курса.** Файлы курса хранятся в UTF-8, а Studio нужен Windows-1251. Как получить текст в этой кодировке, сказано в разделе [«Кодировка Windows-1251»](#кодировка-windows-1251). Проще всего скопировать весь текст программы (с GitHub или из файла архива) и вставить его вместо содержимого `first.c`. Другой способ: скопируйте файл из архива в папку проекта, в дереве проекта слева щёлкните правой кнопкой по Source Files → Add Existing Source File(s) и выберите его, а файл, созданный мастером, уберите из проекта (правой кнопкой по нему → Remove File from Project). В проекте должна остаться одна функция `main()`.

**Проект из нескольких файлов**: все `.c` добавьте в Source Files, все `.h` в Header Files. Studio соберёт все `.c` вместе.

В папке проекта появятся файлы `first.aps` (проект, его открывают двойным щелчком), `first.aws` (раскладка окон) и `first.c`.

## Сборка

1. **Build → Build** (F7).
2. Внизу, в окне Build, смотрите итог: строка `Build succeeded with 0 Warnings...` и размеры: Program (flash) и Data (SRAM) в байтах и процентах заполнения. Предупреждения (warnings) прочитайте, даже если сборка прошла: часть из них означает настоящую ошибку (см. [ниже](#частые-ошибки-компиляции)).
3. Ошибка показывает файл и номер строки, двойной щелчок по ней переносит к этому месту. Исправляйте **первую** ошибку и собирайте снова: остальные часто её следствия.
4. Результат лежит в папке `default` внутри папки проекта: `first.hex` (его прошивают), `first.elf` (для отладчика), `first.lss` (листинг: что получилось в командах процессора), `first.map` (где в памяти лежат функции и переменные). Там же `first.eep` с начальными значениями EEPROM: он нужен, только если они есть в программе ([глава 3](03-si.md), раздел «EEPROM»).

Если сборка «прошла», а `.hex` старый, вы, скорее всего, правили не тот файл: проверьте, какой `.c` подключён к проекту.

Если сборка обрывается сразу с сообщением, что не найден avr-gcc или make, Studio не нашла компилятор: как указать к нему путь, сказано в разделе [«Новый проект»](#новый-проект) (страница Custom Options).

## Прошивка через JTAG ICE

1. Модуль подключён к компьютеру и включён (на панели горит светодиод «Питание» в блоке JTAG).
2. Нажмите кнопку **Con** на панели инструментов (или **Tools → Program AVR → Connect...**).
3. В окне Select AVR Programmer: Platform **JTAG ICE** (не JTAGICE mkII), Port **Auto** или номер COM-порта модуля. Скорость (Baud rate) не трогайте. Нажмите **Connect...**.
4. Откроется окно программатора с заголовком «JTAG ICE in JTAG mode with ATmega16». Если оно не открылось, причины перечислены ниже.
5. Вкладка **Program**, секция **Flash**: Input HEX File, кнопкой «...» выберите `.hex` из папки `default` вашего проекта и нажмите **Program**. Галочки Erase device before flash programming и Verify device after programming оставьте. Внизу окна идёт журнал, в конце каждой строки должно быть `OK`.
6. Программа запускается сама. Если не запустилась, нажмите «Сброс» на модуле.

После каждой новой сборки снова нажимайте Program: путь к `.hex` окно помнит, а сам файл перечитывает при прошивке.

Галочка Erase device стирает перед прошивкой весь кристалл, вместе с EEPROM: так настроены фьюзы стенда (EESAVE выключен).

В окне Select AVR Programmer есть подсказка: кнопка Programmer на панели инструментов подключается к последнему выбранному программатору, минуя это окно. В следующий раз можно нажать её.

**Работайте только на вкладке Program.** Остальные вкладки не нужны, а вкладки Fuses и LockBits опасны: почему, см. [«Фьюзы не трогать»](01-oborudovanie.md#фьюзы-не-трогать).

Если окно программатора не открывается:

- в Platform выбран не JTAG ICE;
- не тот COM-порт: выберите Auto или посмотрите номер в «Диспетчере устройств»;
- номер порта больше COM4: в режиме Auto Studio 4 такой порт может не найти. Выберите номер вручную, а если не помогло, смените его на свободный от COM1 до COM4 (в «Диспетчере устройств» свойства порта → Port Settings → Advanced → COM Port Number), отключите и снова подключите модуль;
- модуль не включён или не подключён, не установлен драйвер FTDI;
- идёт сеанс отладки: отладчик, подключённый к отладке, прошивать не может (в окне об этом прямо написано). Сначала **Debug → Stop Debugging**;
- COM-порт занят другой программой (например, avrdude или терминалом): закройте её.

### Первая проверка

Пройдите всю цепочку на готовой программе [shag1.c](../code/04-porty/shag1.c): светодиод повторяет кнопку. Как она устроена, разобрано в [главе 4](04-porty.md), сейчас проверяются только сборка и прошивка.

1. Соедините проводами гнёзда «Контроллера ПУ»: светодиоды 1–4 с PB4–PB7, одну из кнопок с PC1 (так в блоке ПОДКЛЮЧЕНИЕ в шапке файла, гнёзд занято: 5 из 16). Модуль один, общий провод не нужен.
2. Создайте проект `first` и вставьте текст shag1.c вместо содержимого `first.c` (см. [«Новый проект»](#новый-проект)).
3. Build (F7): в окне Build `Build succeeded with 0 Warnings`.
4. Прошейте `first.hex`, как описано выше.
5. Нажмите и держите кнопку: горит светодиод 1 (PB4), отпустили, погас. Светодиоды 2–4 не горят.

Если не получилось, пройдите [«Сначала пять проверок»](12-ne-rabotaet.md) в главе 12.

## Отладка по шагам

JTAG ICE умеет не только прошивать: программу можно выполнять по строкам прямо на стенде, останавливать и смотреть регистры и переменные. Платформа отладки в проекте должна быть JTAG ICE (см. [«Новый проект»](#новый-проект)).

| Действие | Меню | Клавиши |
|---|---|---|
| собрать, прошить и остановиться в начале `main()` | Build → Build and Run | Ctrl+F7 |
| выполнять дальше | Debug → Run | F5 |
| остановить там, где сейчас выполняется | Debug → Break | Ctrl+F5 |
| начать программу сначала | Debug → Reset | Shift+F5 |
| одна строка, с заходом в функцию | Debug → Step Into | F11 |
| одна строка, функцию выполнить целиком | Debug → Step Over | F10 |
| выйти из функции | Debug → Step Out | Shift+F11 |
| поставить или снять точку останова на строке | Debug → Toggle Breakpoint | F9 |
| закончить отладку | Debug → Stop Debugging | Ctrl+Shift+F5 |

Что смотреть:

- **I/O View** (окно регистров периферии, обычно справа; если закрыто, включается в меню View). Раскройте, например, PORTB: видны DDRB, PINB, PORTB по битам. Пока программа остановлена, бит можно щёлкнуть мышью и изменить регистр.
- **Watch** (окно переменных). Щёлкните правой кнопкой по имени переменной в тексте и выберите Add Watch. Удобно смотреть `t1`–`t4` в часах.
- **Processor**: счётчик команд, указатель стека, регистры R0–R31, SREG.

Попробуйте на shag1.c из [«Первой проверки»](#первая-проверка): Build and Run (Ctrl+F7), поставьте точку останова (F9) на строку `PORTB&= ~0x10;` и нажмите F5. Пока кнопка отпущена, программа работает. Нажали кнопку: программа остановилась на этой строке, а в I/O View у PINC бит 1 равен 0. Позже то же можно сделать на часах из [главы 8](08-chasy.md): точка останова на первой строке обработчика Timer1, и после каждого F5 программа снова останавливается в обработчике, а в Watch видно, как растут секунды.

Что надо знать:

- Пока программа стоит, прерывания не обрабатываются: индикатор замирает с одним горящим разрядом. Это нормально.
- С оптимизацией -Os отладчик иногда перескакивает строки или стоит на одной строке два шага, а локальные переменные показывает не всегда. Глобальные переменные видно всегда.
- Точек останова у отладчика мало (их число ограничено железом): ставьте одну-две.
- Перед прошивкой через Con отладку обязательно закончить: **Debug → Stop Debugging**.
- Build and Run записывает программу во flash. После Stop Debugging она остаётся в микроконтроллере и работает сама.

**Симулятор без стенда.** Если выбрать платформу AVR Simulator, Build and Run запускает программу в модели микроконтроллера на компьютере, стенд не нужен. Окна те же: I/O View, Watch, Processor. Вход кнопки моделируется щелчком по биту PINx в I/O View. В окне Processor есть счётчик тактов и секундомер (Stop Watch): удобно проверять расчёт таймера, например, что между остановками в обработчике Timer1 проходит 8 000 000 тактов. Задайте частоту 8 МГц в Debug → AVR Simulator Options, поле Frequency (пункт есть в меню, пока работает симулятор), иначе время будет посчитано для другой частоты. Симулятор работает медленнее реального времени.

## Кодировка Windows-1251

Studio 4 не знает UTF-8. Свой текст она читает и сохраняет в кодировке Windows, для русской Windows это Windows-1251 (cp1251). Файлы в этом репозитории хранятся в UTF-8: так их правильно показывает GitHub.

Что будет, если открыть в Studio файл в UTF-8: русские комментарии превратятся в «кракозябры». Например, слово «сегменты» станет `СЃРµРіРјРµРЅС‚С‹`. Код при этом соберётся (русские буквы есть только в комментариях), но читать его нельзя. Не сохраняйте такой файл из Studio: заглавная «И» в UTF-8 содержит байт 0x98, которого в Windows-1251 нет, и после сохранения текст может испортиться окончательно.

Обратная ситуация: файл в Windows-1251 в браузере или в VS Code покажет вместо русских букв знаки `�`. В VS Code: Reopen with Encoding → Cyrillic (Windows 1251).

Как получить файлы для Studio:

1. **Архив из Releases.** На странице репозитория в разделе Releases лежит `atmega16-praktikum-cp1251.zip`: все `.c` и `.h` уже в Windows-1251 с переводами строк Windows (CRLF), папки те же, что в `code/`. Скачайте архив, распакуйте его в папку без русских букв и пробелов и добавьте нужный файл в проект. Такой же архив можно собрать из репозитория скриптом [`tools/make_zip.py`](../tools/make_zip.py).
2. **Через буфер обмена.** Откройте файл на GitHub, скопируйте текст (кнопка копирования над файлом или выделение) и вставьте в окно редактора Studio. Windows сама перекодирует текст при вставке. Условие: в Windows для программ, не поддерживающих Юникод, должен быть выбран русский язык (Панель управления → Региональные стандарты → Дополнительно → Изменить язык системы). Иначе русские буквы станут знаками `?`.
3. **Перекодировать самому.**
   - Notepad++: меню «Кодировки» → «Преобразовать в ANSI», сохранить. При русском языке системы ANSI и есть Windows-1251.
   - Блокнот Windows 10 и новее: «Сохранить как», внизу «Кодировка: ANSI».
   - Командная строка (Linux, macOS, Git Bash): `iconv -f UTF-8 -t CP1251 444.c > 444_1251.c`.

Обратно в UTF-8 (например, чтобы открыть свой файл в VS Code или выложить на GitHub): `iconv -f CP1251 -t UTF-8 444_1251.c > 444.c` или в Notepad++ «Преобразовать в UTF-8».

В `.c`-файлах курса только латиница и кириллица, без типографских знаков. Части таких знаков (минус −, знак умножения ×, стрелки) в Windows-1251 нет, при перекодировке они превращаются в `?`. Обычный дефис, две точки `..` и прямые кавычки `"` переносятся без потерь.

Если файл не из архива открылся в Studio без переносов, одной длинной строкой, у него переводы строк в стиле Linux (LF). Пересохраните его в Notepad++ с переводами строк Windows: «Правка» → «Формат конца строк» → «Преобразовать в Windows (CR LF)».

## Частые ошибки компиляции

Сообщения ниже даны так, как их пишут avr-gcc 7.3 и 14.1. Компилятор 4-й серии из Studio 4 местами пишет короче, смысл тот же.

| Сообщение | Что не так |
|---|---|
| `expected ';' before ...` | пропущена `;` в конце **предыдущей** строки |
| `called object is not a function or function pointer` | тоже пропущена `;`, а следующая строка начинается с имени регистра: `DDRB=0xF0` без `;`, за ней `PORTB=0x00;`. Имя регистра раскрывается в выражение со скобками, и компилятор читает `0xF0 (...)` как вызов функции. Сообщение указывает на строку без `;` |
| `'PORTX' undeclared (first use in this function)` | опечатка в имени регистра или переменной, не подключён `<avr/io.h>`, в проекте не выбран микроконтроллер |
| `expected declaration or statement at end of input` | не хватает закрывающей `}` |
| `'else' without a previous 'if'` | лишняя `;` между `}` и `else`: `if(...){...}; else` ([глава 3](03-si.md), раздел «if и else») |
| `stray '\300' in program` и похожие (`\365`, `\320`, `\321`) | русская буква в коде, обычно в имени: `DDRА` с русской «А», `0хFE` с русской «х». На вид не отличить: перенаберите имя в английской раскладке. Число в сообщении это код байта в восьмеричной записи. В файле Windows-1251, как в Studio 4, «А» даёт `\300`, «х» даёт `\365`. В файле UTF-8 avr-gcc до 10-й версии пишет `\320` или `\321` |
| `'DDR\U00000410' undeclared`, `invalid suffix "хFE" on integer constant` | то же самое в avr-gcc 10 и новее с файлом в UTF-8 (так бывает в VS Code или в командной строке с новым компилятором). `\U00000410` это номер русской «А» в Юникоде |
| `'TIMER0_OVF_vec' appears to be a misspelled 'signal' handler` (предупреждение) | опечатка в имени вектора в `ISR()`. Обработчик не вызовется, а при первом же таком прерывании программа начнётся заново, как после сброса. Сверяйтесь со списком векторов ([глава 6](06-preryvaniya.md#векторы-atmega16)) |
| `excess elements in array initializer` (предупреждение) | в фигурных скобках больше значений, чем размер массива: лишние отброшены |
| `redefinition of 'i2'` | переменная объявлена дважды, например при вставке готового фрагмента: удалите одно объявление |
| `'k' undeclared` | переменная используется, но не объявлена: допишите объявление |
| `#warning "F_CPU not defined for <util/delay.h>"` | не задана частота: `#define F_CPU 8000000UL` до всех `#include` |
| `"F_CPU" redefined` (предупреждение) | частота задана в двух местах по-разному: в коде и в поле Frequency проекта |
| `Compiler optimizations disabled; functions from <util/delay.h> won't work as designed` (предупреждение) | в Configuration Options выбрано -O0: поставьте -Os |
| `implicit declaration of function '_delay_ms'` | не подключён заголовок: `<util/delay.h>` для `_delay_ms()`, `<avr/interrupt.h>` для `sei()`. В старом avr-gcc это предупреждение, в новом ошибка |
| `__builtin_avr_delay_cycles expects a compile time integer constant` | в `_delay_ms()` передана переменная. Аргумент должен быть числом, известным при компиляции. Для переменной паузы: `for(k=0; k<t; k++) _delay_ms(1);` |
| `suggest parentheses around comparison in operand of '&'` (предупреждение) | `if(PINC & 0x02 == 0)`: сравнение выполняется раньше `&`, условие всегда ложно. Нужно `if((PINC & 0x02)==0)` ([глава 3](03-si.md#битовые-операции)) |
| `suggest parentheses around assignment used as truth value` (предупреждение) | `if(x = 5)` вместо `if(x == 5)` |
| `` undefined reference to `show' `` | функция объявлена, но не написана, или её `.c` не добавлен в проект |
| `` multiple definition of `count' `` | переменная определена в `.h` (`unsigned char count=0;`), а он подключён в два `.c`. avr-gcc 10 и новее выдаёт это и без `=0`. В `.h` оставьте `extern`, определение в одном `.c` ([глава 3](03-si.md), раздел «static, register, extern») |

### Компилятор промолчит

Эти ошибки собираются без единого предупреждения, а программа работает не так:

| Код | Что не так |
|---|---|
| `MCUCR &= ~(1<<PUD);` | бит PUD у ATmega16 в регистре SFIOR. Имя бита это просто его номер (PUD = 2), поэтому строка компилируется и сбрасывает бит 2 регистра MCUCR, а это ISC10 (условие срабатывания INT1). Подтяжки после сброса и так разрешены, строка не нужна ([глава 4](04-porty.md#подтяжка-и-бит-pud)) |
| `TIMSK = (1<<OCIE1A);` | `=` переписал весь регистр и выключил разрешённое раньше прерывание Timer0. Нужно `TIMSK\|= (1<<OCIE1A);` |
| `if(PORTC & 0x02)` | кнопку читают из PINC: в PORTC лежит то, что записали вы, а не уровень на выводе |
| `PORTB=0xF0;` при кнопке на PB2 | запись целого байта выключила подтяжку входа PB2 ([глава 4](04-porty.md#регистры-ddr-port-pin)) |
| `char c=0xE0; if(c==0xE0)` | без `-funsigned-char` условие ложно ([глава 3](03-si.md#типы-данных-на-avr)). Предупреждение будет, только если добавлен `-Wextra` |

Больше симптомов и причин: [глава 12](12-ne-rabotaet.md).

## Командная строка (справочно)

Studio вызывает те же программы, что можно запустить вручную. Так собирают без Studio, например в VS Code или на Linux:

```
avr-gcc -mmcu=atmega16 -Os -Wall -std=gnu99 -funsigned-char -funsigned-bitfields -fpack-struct -fshort-enums -o main.elf main.c
avr-objcopy -O ihex -R .eeprom main.elf main.hex
avr-size main.elf
avrdude -p m16 -c jtag1 -P COM5 -U flash:w:main.hex:i
```

- `avr-gcc` компилирует. Проект из нескольких файлов: все `.c` в одну команду (`main.c display.c buttons.c`). Заголовки `.h` в команду не пишут, их подключает `#include`.
- `avr-objcopy` делает из `.elf` файл `.hex` для прошивки. `-R .eeprom` выкидывает начальные значения EEPROM: они прошиваются отдельно.
- `avr-size` показывает размер: `text + data` занимают flash, `data + bss` занимают SRAM.
- `avrdude` прошивает: `-p m16` это ATmega16, `-c jtag1` это JTAG ICE mk1, `-P COM5` порт модуля (свой номер смотрите в «Диспетчере устройств»; в Linux порт вида `/dev/ttyUSB0`). Пока порт открыт в Studio, avrdude к нему не подключится, и наоборот.

Все программы курса собираются такими же командами (с `-Wall -Wextra`, без единого предупреждения), это проверяют скрипты в папке [`tests/`](../tests/).
